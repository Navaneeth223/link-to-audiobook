# Audiobook export

## What is implemented

Audiobook export is available for locally sample-producing Piper speech only. The existing browser/OS
`SpeechSynthesis` voice cannot expose its generated audio samples. Its export choice is disabled with an
explanation and a one-click switch to the downloadable Piper voice; system audio recording is not used.
The current build offers one eligible voice, US English LibriTTS high (speaker p3922). Voice Studio and
bring-your-own-key cloud voices are not implemented.

The export pipeline runs in a dedicated Web Worker: document chapters and paragraphs are split using the
reader's sentence chunker, each chunk is synthesized locally, normalized, cached as mono PCM in OPFS, and
encoded incrementally. The output choices are MP3 per chapter in a ZIP (default), a single MP3 with ID3v2
CHAP/CTOC metadata, and mono 24 kHz/16-bit PCM WAV. M4B/AAC is not offered because a reliable chapter-aware
browser muxer is not implemented. Files include title, author, voice, and “Generated by Private Story Reader”
metadata. The selected text and generated audio are not sent to a server; downloading the model and runtime
does make ordinary requests to their pinned public hosts.

The dialog supports selecting all chapters, a subset, or the current chapter, and editing the title and author.
It honors the selected narration speed and volume and inserts actual silence between paragraphs and chapters.
Pitch and pronunciation dictionaries are not available in the current reader. It estimates audio duration,
output size, and generation time; a user can benchmark the first three sentences on their device. The estimate
is device-specific and is not a guarantee. The first benchmark may download the approximately 137 MB model.

Exports are limited to 10 estimated hours per job. MP3 chapter files and intermediate PCM are written to OPFS;
where the File System Access API is supported, the final result can be streamed directly to a user-selected
file. Other browsers use OPFS and a local download link. A matching interrupted job can be restored from its
saved settings and resumed from cached chunks. Pause/resume, cancel, retry, a screen wake lock where available,
and per-chunk progress are implemented. The completed output and resumable chunks remain in OPFS only while
the finished dialog is open so the user can download and preview without buffering the whole book in memory.
Closing the dialog, choosing **Done**, or choosing **Delete generated audio** removes the export and its
unshared PCM cache. **Export another format** removes the previous output but keeps reusable chunks during the
next export. Cancelled exports are removed. Clear cached audio and Clear everything also remove audiobook
cache data; Clear everything attempts to remove the downloaded Piper model and reports whether storage cleanup
succeeded. Files explicitly saved or downloaded by the user remain under their control.

## Formats, size, and memory

MP3 uses a separate JavaScript LAME encoder at a selectable 64, 96, or 128 kbps mono. Approximate encoded
payload sizes per hour are 28.8, 43.2, and 57.6 MB, respectively, plus metadata and ZIP overhead. WAV is
approximately 172.8 MB per hour at 24 kHz, 16-bit mono, before container overhead; the UI shows a size warning.
Chapter and sentence names are sanitized before they become file names.

Audio is synthesized and encoded a chunk at a time rather than retaining the entire book's PCM in memory.
Intermediate PCM and chapter MP3 files are written into origin-private storage. ZIP and single-MP3 assembly
stream from those files into the selected file or OPFS. The browser's final download link references a local
file object; browser download implementations may still impose their own memory and size limits. There is no
standard browser API to reserve disk space, so quota checks are advisory and storage write failures remain
possible.

## Generation speed and model/runtime download

There is no fixed generation speed. The current Piper voice uses ONNX Runtime Web/WASM and Piper phonemization;
this implementation does not select a WebGPU backend. Speed varies with processor, memory pressure, browser,
thermal throttling, and voice settings. No measured benchmark is reported for this development machine because
the model was not downloaded or run here; the model alone is approximately 137 MB, exceeding the local free
space recorded during implementation. Do not treat the rough default estimate or any other device's benchmark
as a promise.

The user must remain on the page while generation is active. A screen wake lock is requested where available,
but browsers can deny it or suspend a background tab. Battery-saver mode is not detected. The voice model is
stored in OPFS and can be removed in the device-data viewer or by **Clear everything**. Runtime WASM files
are fetched with browser cache disabled and used in worker memory; the app does not persist them.

## Browser and device support

| Browser family     | Export path                                                        | Status and limits                                                                                                                                            |
| ------------------ | ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Chromium desktop   | File System Access API when available; OPFS for working data       | Preferred path. Chromium smoke/accessibility and responsive viewport tests run in CI. Model inference has not been exercised on this machine.                |
| Chromium Android   | OPFS plus browser download; direct save depends on browser/version | Feature-detected, but mobile storage, memory, and background throttling may limit long books.                                                                |
| Firefox desktop    | OPFS plus browser download                                         | FSA direct save is generally unavailable. The code has an OPFS fallback, but Firefox E2E and large-file behavior have not been verified in this environment. |
| Safari macOS       | OPFS plus browser download                                         | FSA direct save is generally unavailable. Safari behavior has not been verified here.                                                                        |
| Safari iPhone/iPad | OPFS plus browser download where supported                         | Tight storage, memory, and background limits make large exports unreliable; prefer a single chapter and keep the tab open. Not verified here.                |

Storage APIs and download behavior are feature-detected. A quota estimate cannot guarantee that a later write will
succeed. If a large book is selected, export chapters separately. Unsupported or unverified platform behavior
must not be presented as a guarantee.

## Privacy, retention, and rights

Story text is passed to a local Web Worker for synthesis and is not written into the export manifest. The cache
key is a one-way digest derived from the document fingerprint, voice/provider, speed, and chunk text; the stored
audio chunks are local OPFS files only while an export is active, resumable, or its finished dialog is open.
The manifest stores only settings, document fingerprint, chapter identifiers and labels, timestamps, and
completed chunk references. Model and runtime downloads are the only network
requests introduced by export; no story text or generated audio is sent over the network.

The interface displays and requires acceptance of: “For personal listening. You are responsible for having the
right to convert this document. Do not redistribute content you don't own.” Exports are for the user's personal
listening. The user is responsible for rights to the source document and any generated file. Do not share or
publish export features. Voice Studio is not implemented; if added later, an exported voice must be the user's
own voice with a valid consent record.

## License records and checks

The current Piper runtime, phonemizer, ONNX Runtime, voice model, MP3 encoder, and ZIP implementation and their
license notes are listed in [THIRD_PARTY_LICENSES.md](../THIRD_PARTY_LICENSES.md). The eSpeak NG source revision
embedded by the published Piper WASM package is not disclosed by its build instructions; that provenance
limitation is recorded and must be reviewed before redistributing a different runtime artifact.

The latest validation on this branch passed `npm run check` (typecheck, lint, and 51 unit tests across 13
files), `npm run build`, `npm run test:e2e` (22 passed and 20 intentionally skipped), and `npm run test:visual`
(7 passed and 5 intentionally skipped). E2E runs six Chromium viewport profiles; export-control, reload
recovery, and download flows are desktop-only mocked-worker tests. The visual suite attaches dialog screenshots
for all four themes and runs axe against the dialog at desktop size; it does not maintain image-diff baselines.
Unit coverage validates PCM normalization, silence, WAV/MP3 metadata, ZIP safety, estimates, cache keys, and
resumable manifest validation. The exported ZIP download path is checked with mocked output bytes. Live Piper
inference, real audio output parsing, Firefox/WebKit export, storage-full behavior, and long-book memory behavior
remain unverified.
